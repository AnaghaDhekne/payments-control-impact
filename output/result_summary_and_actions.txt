SECTION 4: CORRECTED KEY FINDINGS (36-CASE, 5-RUN DEVELOPMENT)
================================================================================

1. RECOVERY IS BORDERLINE — 49.5% (gate: 50%)
   The hybrid recovers 111 of 225 missed key controls on average.
   Runs 3-4 individually pass (50.2%); runs 1, 2, 5 fail (48.9-49.3%).
   This is not robust — the system is right at the threshold.

2. WORKLOAD IS THE PRIMARY BLOCKER — 201.5% (gate: 25%)
   The hybrid surfaces 531 controls for review vs 176 baseline.
   The UNCERTAIN queue alone (242 controls) exceeds the entire
   baseline workload. The 25% gate allows only ~44 extra controls;
   the system surfaces 355 extra. This is 8x over the threshold.

3. 114 KEY CONTROLS NEVER SURFACED AT ALL
   114 key-control pairs across 36 cases are never surfaced by
   either baseline or LLM. This is a 41% residual miss rate.
   Candidate retrieval (Jaccard token overlap) is not finding
   these controls in the top-20 candidates.

4. 160 FALSE POSITIVES PER RUN
   ~160 controls are surfaced as AFFECTED or UNCERTAIN but are
   not actually affected per ground truth. This contributes
   significantly to workload inflation.

5. RUN-TO-RUN AGREEMENT: 85.9% (gate: 95%)
   14% of key-control decisions vary across 5 runs.
   The LLM is not sufficiently deterministic at temperature 0.
   Concern for audit/compliance where reproducibility is required.

6. ZERO PARSE FAILURES ACROSS 180 LLM CALLS
   The structured JSON response contract held perfectly across
   all 36 cases x 5 runs. Prompt design is robust.

7. THE UNAFFECTED BUG FIX CHANGED EVERYTHING
   Previous report (with bug): 68.3% recovery, 442% workload.
   Corrected (bug fixed): 49.5% recovery, 201.5% workload.
   The bug was inflating both metrics by including UNAFFECTED
   controls in recommendations. All previous claims are superseded.


SECTION 5: DEVELOPMENT EXPERIMENTS (NEXT STEPS)
================================================================================

EXPERIMENT D: RANK AND CAP LLM ADDITIONS (HIGHEST PRIORITY)
--------------------------------------------------------------------------------
Problem:  Workload is 201.5% (8x over the 25% gate). The LLM surfaces
          531 controls when baseline surfaces 176.
Status:   The UNAFFECTED bug is already fixed. But 201.5% still exceeds
          the 25% gate by 8x.
Action:   Rank LLM-only AFFECTED by confidence + evidence quality.
          Keep UNCERTAIN in a separate counted queue. Test multiple
          reviewer-budget operating points. Show a recall-workload frontier.
          Do not cap solely to meet the target if key misses rise.
Note:     A 25% increase over 176 baseline allows only ~44 extra controls.
Ref:      docs/evaluation_improvement_plan.md, Experiment D

PRIORITY 2: CAP LLM ADDITIONS TO TOP N BY CONFIDENCE (MEDIUM IMPACT)
--------------------------------------------------------------------------------
Problem:  Even after confidence filtering, LLM may flag 15-20 controls as
          AFFECTED with high confidence, still exceeding workload budget.
Action:  After filtering by confidence >= 0.8, sort remaining LLM-only
          additions by confidence descending and keep only the top 10.
Expected: Workload increase further reduced to under 100% at 30% correlated.
Code:    scripts/hybrid.py, hybrid_rank_controls() function

PRIORITY 3: ADD GRAPH-FAMILY-AWARE CANDIDATE RETRIEVAL (MEDIUM IMPACT)
--------------------------------------------------------------------------------
Problem:  At 60% random degradation, recovery rate is only 37% (below 40%).
          Jaccard token overlap is too weak when text is also degraded.
Action:  In retrieve_control_documents(), add a bonus score for controls
          in the same family as any baseline-flagged control. Family
          metadata is visible in the degraded graph (node attribute).
Expected: Recovery at 60% random improves from 37% to likely 45%+.
          May flip 60%/random recovery from FAIL to PASS.
Code:    scripts/hybrid.py, retrieve_control_documents() function

PRIORITY 4: INCREASE TOP_K FROM 20 TO 30 (LOW IMPACT)
--------------------------------------------------------------------------------
Problem:  With only 20 candidates, some genuinely impacted controls may
          not be in the candidate set at high degradation.
Action:  Increase default top_k from 20 to 30 in evaluate_hybrid.py CLI
          default and in hybrid_rank_controls() default.
Expected: Marginal recovery improvement at all degraded conditions.
Code:    scripts/evaluate_hybrid.py, scripts/hybrid.py

PRIORITY 5: IMPROVE RUN-TO-RUN AGREEMENT (MEDIUM IMPACT)
--------------------------------------------------------------------------------
Problem:  Agreement drops to 94.7% under correlated degradation.
          Not perfectly deterministic even at temperature 0.0.
Action:  Option A: Try databricks-meta-llama-3-3-70b-instruct or
                  databricks-gpt-oss-120b (may be more deterministic).
          Option B: Run 2 LLM calls per case, take intersection of AFFECTED
                  controls. Guarantees consistency but doubles cost.
          Option C: Add prompt instruction: 'Be consistent. If uncertain,
                  mark UNCERTAIN rather than AFFECTED.'
Expected: Agreement improves to 100% with Option B (intersection).
Code:    scripts/databricks_llm.py, scripts/hybrid.py, scripts/evaluate_hybrid.py

PRIORITY 6: ADD DETERMINISTIC FALLBACK FOR INCONSISTENT DECISIONS (LOW IMPACT)
--------------------------------------------------------------------------------
Problem:  When the LLM gives different answers across runs, there is no
          deterministic fallback mechanism.
Action:  In evaluate_hybrid.py, when runs disagree on a control, default
          to the baseline recommendation. Only add an LLM-only control if
          ALL runs agree.
Expected: Agreement effectively becomes 1.0 for the final decision set.
          May slightly reduce recovery rate, but improves auditability.
Code:    scripts/evaluate_hybrid.py, evaluate_hybrid() function


SECTION 6: RECOMMENDATION (CORRECTED)
================================================================================

The hybrid approach (baseline + LLM) is NOT READY FOR PILOT.

All three POC gates fail on the primary condition (30% correlated):
  - Recovery 49.5% (borderline, just below 50% threshold)
  - Workload 201.5% (8x over the 25% threshold)
  - Agreement 85.9% (below the 95% threshold)

The previous report's claim of READY FOR PILOT was based on incorrect
criteria, a case-count mismatch (5 vs 18), and the UNAFFECTED bug.

NEXT STEPS (per docs/evaluation_improvement_plan.md):
  1. Experiment D: Rank and cap LLM additions by confidence to reduce
     workload from 201% toward the 25% threshold.
  2. Experiment B: Improve candidate retrieval to reduce 114 excluded
     key misses.
  3. Experiment F: Lineage repair comparator — determine whether simply
     fixing metadata recovers as much recall with lower workload.
  4. Experiment E: Test alternate models or 2-call intersection for
     stability to improve agreement from 85.9% toward 95%.
  5. After development experiments, lock the procedure and run the
     held-out test split ONCE as confirmation.

A pilot requires: zero observed key-control misses in surfaced
AFFECTED+UNCERTAIN, sampled review of excluded controls, sample size,
and an uncertainty bound (rule of three: ~3/n when zero misses observed).
